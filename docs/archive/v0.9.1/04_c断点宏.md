# 04 C 断点宏

只验证架构链路有没有走到。预编译开关，默认关。  
**不是日志**：无等级、无文本、不走 `Transport_Write` 发诊断帧、不增加第三 SOF。

Python 对等物是 [03 `trace.debug`](03_python_trace.md)，不在本文件做第二套。本文件与 Python `debug.bp` 同属切片 **C**，必须在切片 A 之后做：`STNP_BP_ON_NOTIFY` 只打独占后实际认领的那一条。

## 开关

头文件：`templates/c/Core/stnp_debug.h.j2` → `Core/stnp_debug.h`。  
实现：`templates/c/Core/stnp_debug.c.j2` → `Core/stnp_debug.c`。

```c
#ifndef STNP_DEBUG
#define STNP_DEBUG 0
#endif
```

这就是全部运行时策略。`0`：宏展开为空。`1`（编译选项 `-DSTNP_DEBUG=1`）才调用 trap。  
**禁止** `Enable()` 运行时函数。**禁止** `STNP_LOG` / `STNP_LOGE` / `STNP_LOG_LEVEL`。

```c
typedef enum {
    STNP_BP_SITE_RX_COPY = 0,
    STNP_BP_SITE_PROCESS_ENTER,
    STNP_BP_SITE_PARSE_OK,
    STNP_BP_SITE_PARSE_RESYNC,
    STNP_BP_SITE_ENQUEUE,
    STNP_BP_SITE_ROUTE_FAIL,
    STNP_BP_SITE_DISPATCH,

    STNP_BP_SITE_SEQ_RESERVE,
    STNP_BP_SITE_TRANSPORT_WRITE

#if STNP_DEBUG
void STNP_Debug_Trap(STNP_BpSite site);
#define STNP_BP_RX_COPY()          STNP_Debug_Trap(STNP_BP_SITE_RX_COPY)

#define STNP_BP_PARSE_RESYNC()     STNP_Debug_Trap(STNP_BP_SITE_PARSE_RESYNC)
#define STNP_BP_ENQUEUE()          STNP_Debug_Trap(STNP_BP_SITE_ENQUEUE)
#define STNP_BP_ROUTE_FAIL()       STNP_Debug_Trap(STNP_BP_SITE_ROUTE_FAIL)
#define STNP_BP_DISPATCH()         STNP_Debug_Trap(STNP_BP_SITE_DISPATCH)

#define STNP_BP_SEQ_RESERVE()      STNP_Debug_Trap(STNP_BP_SITE_SEQ_RESERVE)
#define STNP_BP_TRANSPORT_WRITE()  STNP_Debug_Trap(STNP_BP_SITE_TRANSPORT_WRITE)
#else
#define STNP_BP_RX_COPY()          ((void)0)
#define STNP_BP_PROCESS_ENTER()    ((void)0)
#define STNP_BP_PARSE_OK()         ((void)0)
#define STNP_BP_PARSE_RESYNC()     ((void)0)
#define STNP_BP_ENQUEUE()          ((void)0)
#define STNP_BP_ROUTE_FAIL()       ((void)0)
#define STNP_BP_DISPATCH()         ((void)0)
#define STNP_BP_ON_TASK()          ((void)0)
#define STNP_BP_ON_NOTIFY()        ((void)0)
#define STNP_BP_SEQ_RESERVE()      ((void)0)
#define STNP_BP_TRANSPORT_WRITE()  ((void)0)

```

宏名与上表必须一一对应。禁止增加未列出的站点。

`stnp_platform_config.h.j2` **禁止** `#define STNP_DEBUG 1`。  
`stnp.h.j2` 必须 `#include "stnp_debug.h"`。

`STNP_Debug_Trap` 默认 **weak 空实现**，包在 `#if STNP_DEBUG` 里。测试夹具提供强符号做计数。  
`STNP_Debug_Trap` 的 weak 默认体必须是：`STNP_UNUSED(site);`，再加且仅加：

```c
#if defined(STNP_DEBUG_TRAP_BKPT) && (STNP_DEBUG_TRAP_BKPT == 1)
    __BKPT(0);
#endif
```

未定义 `STNP_DEBUG_TRAP_BKPT` 时禁止 BKPT。仓库测试编译 **禁止** 传入 `-DSTNP_DEBUG_TRAP_BKPT=1`。测试夹具用强符号计数 trap 覆盖 weak。

## 插入点（对照 `c_runtime.md`）

每个宏在列出的文件里插入 **恰好一次语义点**（Task/Notify 对称的两处 Parse 失败算同一宏名的两处调用点，这是允许的）。插入用「函数名 + 前/后」，0.9.0 行号只是锚点。

### 接收

| 宏 | 文件 | 插入规则 |
|---|---|---|
| `STNP_BP_RX_COPY()` | `templates/c/Core/stnp_core.c.j2` `STNP_Transport_Receive` | **必须**在 `g_rx_tail = tail;` **之后**、`return STNP_OK;` **之前**。参数错误 / `STNP_ERR_BUFFER` 返回路径禁止打。本函数 IRQ 可达；trap 必须极短（计数或 BKPT）。禁止在此构帧、回调、发送。 |
| `STNP_BP_PROCESS_ENTER()` | `stnp_core.c.j2` `STNP_Process` | 函数入口第一句（进入 `for(;;)` 之前）。 |
| `STNP_BP_PARSE_OK()` | `stnp_core.c.j2` `_try_complete_frame` | `STNP_Frame_ParseTask` / `ParseNotify` 成功之后、调用 `STNP_Runtime_EnqueueTask` / `EnqueueNotify` **之前**。Task 与 Notify 各一处。 |
| `STNP_BP_PARSE_RESYNC()` | `stnp_core.c.j2` `_try_complete_frame` 与 `STNP_Process` | **只**打 return 式 LEN/CRC 路径，见下。 |
| `STNP_BP_ENQUEUE()` | `templates/c/Core/stnp_runtime.c.j2` `_enqueue` | `STNP_Runtime_Unlock` 成功路径之后、`return STNP_OK` 之前。Task 与 Notify 共用这一处。队列满返回 `STNP_ERR_BUFFER` 禁止打。 |
| `STNP_BP_ROUTE_FAIL()` | `stnp_runtime.c.j2` `STNP_Runtime_EnqueueTask` | `STNP_Router_ResolveTask` 返回值 `!= STNP_OK` 时，在 `return result` **之前**。Notify 入队无 Router，禁止打。 |
| `STNP_BP_DISPATCH()` | `stnp_runtime.c.j2` `STNP_Runtime_DispatchOne` | `_claim_runnable` 成功之后、`task_handler` / `STNP_Notify_Dispatch` **之前**。claim 失败返回 `STNP_IDLE` 禁止打。 |
| `STNP_BP_ON_TASK()` | `templates/c/Module/module/module.c.j2` `<Module>_OnTask` | 函数入口、`self == NULL` 判断之后即将进入 VTL/switch 之前。每个 Module 生成一份，语义点相同。 |
| `STNP_BP_ON_NOTIFY()` | `templates/c/Instance/stnp_instances.c.j2` `STNP_Notify_Dispatch` | **必须在切片 A 独占路由之后**。见下。禁止打进 `<Module>_NotifyCallback` 与 `STNP_Notify_Callback` 函数体（会与 instances.c 重复，0.9.0 并行下还会打两次）。 |

### `PARSE_RESYNC` 允许 / 禁止

**必须打**（均在 `_parse_shift` 之后、`return` 之前，或与 unknown Report 同路径时：Report 在 shift 前、本宏在 shift 后 return 前均可，但同一 return 只打一次）：

1. `_try_complete_frame`：`payload_len > STNP_PAYLOAD_MAX`（Task / Notify）→ 返回 `STNP_ERR_LENGTH`
2. `_try_complete_frame`：`STNP_Frame_ParseTask` / `ParseNotify` 失败 → 返回该错误码
3. `STNP_Process`：`g_parse_len >= STNP_FRAME_MAX_SIZE` → 返回 `STNP_ERR_LENGTH`

**禁止打**：

```c
/* _try_complete_frame SOF 猎寻热循环。0.9.0 锚点约 L101–105 */
if ((is_task == 0U) && (is_notify == 0U))
{
    _parse_shift(1U);
    continue;   /* 禁止 STNP_BP_PARSE_RESYNC */
}
```

### `ON_NOTIFY`（依赖 A）

只在 `stnp_instances.c.j2` 的 `STNP_Notify_Dispatch`：

1. 模块独占成功（`IsEnabled` 已查、`NotifyDispatch` 返回 `STNP_OK`）：在 `return r` **之前**打一次。`<Module>_NotifyCallback` 已在 Dispatch 内返回前执行；这是 instances.c 规定的观察点，禁止再在 callback 里打一次。
2. 落入全局：在 `STNP_Notify_Callback(...)` **之前**打一次。
3. 模块 decode 失败（返回值不是 `STNP_OK` 也不是 `STNP_ERR_COMMAND`）：**禁止**打（没有用户回调）。
4. 未知码落入全局：只走第 2 条，禁止在调用 `NotifyDispatch` 前预打。

0.9.0 并行下若两处都打，enable 后会得到两次 `ON_NOTIFY`。0.9.1 一帧最多一次。

### 发送

| 宏 | 文件 | 插入规则 |
|---|---|---|
| `STNP_BP_SEQ_RESERVE()` | `templates/c/Core/stnp_frame.c.j2` `STNP_Frame_ReserveSeq` | 取出 `seq`、`_seq_advance` 与 Unlock 之后、`return seq` 之前。该函数本身包在 `{% if p.seq_enabled %}` 里；seq 关闭时禁止在其它文件冒出本宏。 |
| `STNP_BP_TRANSPORT_WRITE()` | `stnp_core.c.j2` `STNP_Transport_Write` | 参数检查通过之后、调用已登记 `g_transport_write(data, length)` **之前**。`write_fn == NULL` / 参数错误返回路径禁止打。禁止在此塞文本或改 buffer。 |

头文件 `stnp_debug.h` 仅宏 + `STNP_BpSite` + trap 声明。禁止在此头做 Log API。

使用宏的 `.c` 必须能看到声明：经由 `stnp.h` 或直接 `#include "stnp_debug.h"`。`stnp_core.c.j2` / `stnp_runtime.c.j2` / `stnp_frame.c.j2` / `stnp_instances.c.j2` / `module.c.j2` 缺 include 则必须补。

## 输出示例（测试夹具）

编译加 `-DSTNP_DEBUG=1`，覆盖 `STNP_Debug_Trap` 记 site。喂一帧合法 Task：

```text
RX_COPY, PROCESS_ENTER, PARSE_OK, ENQUEUE, DISPATCH, ON_TASK
```

CRC 错：含 `PROCESS_ENTER`、`PARSE_RESYNC`；无 `PARSE_OK`、`ON_TASK`。

`STNP_DEBUG=0`（golden 默认）：除 `stnp_debug.h` / `stnp_debug.c` 外，生成的 `.c` **禁止**出现标识符 `STNP_Debug_Trap`。允许出现 `STNP_BP_*()` 宏调用（展开为空）。

## 测试

1. 同一份生成树必须编译两次：默认（`STNP_DEBUG` 为 0）一次；`-DSTNP_DEBUG=1` 一次。两次都要 `-Wall -Wextra -Werror`。
2. `DEBUG=1` 夹具用强符号计数 trap，合法 Task 站点序列如上；禁止默认 BKPT。
3. golden 按 `DEBUG=0` 生成。
4. Enable 后独占 Notify：`ON_NOTIFY` 次数为 1，不是 2。

## 生成器

- `emit/c/emitter.py` 的 `core_names` 必须加入 `stnp_debug.h`、`stnp_debug.c`
- `CMakeLists.txt.j2` Core 列表必须加入 `stnp_debug.c`
- `ir/builder.py` `fixed_public_symbols` 必须加入 `STNP_Debug_Trap`、`STNP_BpSite`

## 明确禁止

- `STNP_LOGE` / `STNP_LOG_LEVEL` / `STNP_LOG`
- 诊断信封、log SOF、parser skip 第三家族
- Python `on_log`
- 在 IRQ 里做业务（解析 / 用户回调 / 发送）。`STNP_BP_RX_COPY` 是唯一允许出现在 `Transport_Receive` 里的 trap，且 `DEBUG=0` 时为零
