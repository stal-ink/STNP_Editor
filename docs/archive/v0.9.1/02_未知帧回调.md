# 02 未知帧回调

0.9.0 对非指定 SOF、LEN/CRC 失败、不可路由 Task、Python 未知 Notify **静默丢弃**（或只记内部计数）。0.9.1 给出 **同一个回调 + 使能函数**，默认关。开了之后怎么处理交给用户：运行时禁止自动打印、禁止自动重传。

本切片为 **B**。Python 未知 Notify 的「无人认领」定义依赖切片 A 的独占链。禁止在 0.9.0 并行语义上实现 NOTIFY 分类。

RING / `StreamParser.buffer` 仍是字节缓冲。  
**禁止**在 `STNP_Transport_Receive` / `transport.read` 里预处理、解析或回调。  
**禁止**诊断信封、第三 SOF、parser skip 第三家族。parser 仍然只认两个协议 SOF。

## 0.9.0 现状（对照用）

| 情况 | C | Python |
|---|---|---|
| 非 Task/Notify SOF | `_try_complete_frame` 滑 1 字节，无回调 | `_find_sof` 失败则 `del self.buffer[:-1]`，一次丢掉前缀 |
| `LEN > max_payload` | 滑 1，返回 `STNP_ERR_LENGTH` | `protocol_errors++`，`del self.buffer[0]` |
| CRC / 结构失败 | 滑 1，返回错误码 | `crc_errors++`，`del self.buffer[0]` |
| Task 目标 / 命令无法路由 | 整帧消费后不入队，无用户回调 | `ProtocolError` 被 `_dispatch_frame` 吃进 `callback_errors` |
| 未知 Notify | 入队后走全局（weak/强符号恒存在） | 有 `@stnp.on_notify` 给 raw bytes；否则丢 |

## API

### C

新文件：`templates/c/Core/stnp_unknown.h.j2`、`stnp_unknown.c.j2`。生成路径 `Core/stnp_unknown.h` / `Core/stnp_unknown.c`。

```c
typedef enum {
    STNP_UNKNOWN_SOF    = 0x01U, /* 仅当 STNP_UNKNOWN_REPORT_SOF=1 才上报 */
    STNP_UNKNOWN_LEN    = 0x02U,
    STNP_UNKNOWN_CRC    = 0x03U, /* CRC 或 Frame_Parse* 结构失败 */
    STNP_UNKNOWN_TASK   = 0x04U, /* 完整 Task 帧，Router 不可路由 */
    STNP_UNKNOWN_NOTIFY = 0x05U  /* 枚举保留；C 0.9.1 禁止触发 */
} STNP_UnknownReason;

typedef void (*STNP_UnknownFrameFn)(
    STNP_UnknownReason reason,
    const STNP_U8 *data,   /* 禁止持有指针出函数；需要则当场拷贝 */
    STNP_U16 length
);

void STNP_UnknownFrame_SetCallback(STNP_UnknownFrameFn fn); /* NULL = 清除 */
void STNP_UnknownFrameCallback_Enable(STNP_EnableState state); /* 默认 STNP_DISABLE */
STNP_U8 STNP_UnknownFrameCallback_IsEnabled(void);

/* Core 内部；用户禁止依赖。data==NULL 且 length>0 时禁止调用用户 fn。 */
void STNP_UnknownFrame_Report(
    STNP_UnknownReason reason,
    const STNP_U8 *data,
    STNP_U16 length
);
```

内部状态：函数指针默认 `NULL`，使能默认 `STNP_DISABLE`。  
`Report()` **仅当** `fn != NULL` **并且** `IsEnabled() != 0` 才调用用户 fn。任一不满足必须立即返回。  
**禁止** weak 空函数每帧都进：关必须是真零调用。

`STNP_UNKNOWN_NOTIFY`：枚举值必须保留。C 实现 **禁止** 对任何路径调用 `Report(..., STNP_UNKNOWN_NOTIFY, ...)`。原因：Core weak + Implementation 强符号让全局恒可调用，独占链末端不存在「无人认领」。

上下文：Parse / Enqueue 在 `STNP_Process`（含它调用的 `_try_complete_frame`）。IRQ 里仍然只允许 `STNP_Transport_Receive`。

### Python

包入口 `templates/python/stnp/__init__.py.j2` 必须导出：

```python
@stnp.on_unknown_frame
def on_unknown(reason: str, data: bytes) -> None:
    ...

stnp.unknown_frame_callback_enable()
stnp.unknown_frame_callback_disable()
stnp.unknown_frame_callback_is_enabled() -> bool
```

`reason` 取值只能是 `"sof" | "len" | "crc" | "task" | "notify"`。

状态 **必须**在 `Runtime` 上，字段恰好这三个（禁止改名、禁止再加第四个开关）。`Runtime.__init__` **必须**赋这些初值：

```python
_unknown_callback: Callable | None = None   # collections.abc.Callable
_unknown_enabled: bool = False
unknown_report_sof: bool = False
```

`unknown_report_sof` 是 SOF 的第二开关，不是主开关。**禁止**把它当成 Enable。

`@stnp.on_unknown_frame` **必须**与 `on_notify` 同一模式：只把 `fn` 赋给 `_unknown_callback` 并 `return fn`。**禁止**自动 enable（**禁止**把 `_unknown_enabled` 写成 `True`）。

```python
# Runtime
def on_unknown_frame(self, fn):
    self._unknown_callback = fn
    return fn

# stnp/__init__.py.j2
def on_unknown_frame(fn):
    return _runtime.on_unknown_frame(fn)
```

`unknown_frame_callback_enable()` **必须**只写 `_unknown_enabled = True`；`disable()` 只写 `False`；`is_enabled()` 只读该 bool。

`_report_unknown(reason: str, data: bytes) -> None` **必须**如下（两道闸在函数内部，与 C `STNP_UnknownFrame_Report` 相同）：

```python
def _report_unknown(self, reason: str, data: bytes) -> None:
    if (not self._unknown_enabled) or (self._unknown_callback is None):
        return
    try:
        self._unknown_callback(reason, data)
    except Exception:
        # 必须隔离。禁止 increment stats.callback_errors。
        # 允许 logging.getLogger("stnp").exception(...)；不是正确性条件。
        return
```

- **禁止**再抛到 `_dispatch_frame`
- **禁止**增加 `stats.callback_errors`
- 内部 `logging.exception` **允许**，**不是**正确性要求（测试禁止依赖这条日志）

调用方对 reason `"sof"`：**必须**在 `unknown_report_sof is False` 时 **禁止**调用 `_report_unknown("sof", ...)`（parser 不 yield SOF `ParseError`；`_rx_loop` 也禁止补报）。两闸检查仍留在 `_report_unknown` 内，禁止把 SOF 第二开关塞进 `_report_unknown`。

C：`STNP_UnknownFrame_Report` 保持上文两道闸（`fn != NULL` **并且** `IsEnabled() != 0`）。SOF 第二开关留在调用点（`STNP_UNKNOWN_REPORT_SOF`）。`data==NULL && length>0` 时 **禁止**调用用户 fn（也 **禁止**以该组合调用 `Report`）。

## `StreamParser` / `ParseError`

`templates/python/stnp/core/frame.py.j2`：

```python
@dataclass(frozen=True, slots=True)
class ParseError:
    reason: str    # "sof" | "len" | "crc"
    data: bytes
```

`TaskFrame` / `NotifyFrame` 必须在现有字段末尾增加 `raw: bytes = b""`。`StreamParser` 产出的帧必须把本次消费的整段候选（SOF+头+payload+CRC，即现在的 `raw = bytes(self.buffer[:total])`）写入 `.raw`。发送路径四参数构造函数保持可用。

`StreamParser.feed` **禁止**直接调用户。返回类型必须是 `list[TaskFrame | NotifyFrame | ParseError]`。

`StreamParser.report_sof: bool = False`。`Runtime._rx_loop` 在每次 `feed` **之前**必须执行 `parser.report_sof = self.unknown_report_sof`。

- `report_sof is True`：每丢掉 1 字节 SOF 猎寻，`out.append(ParseError("sof", bytes([that_byte])))`
- `report_sof is False`：同样每次只滑 1 字节，但 **禁止** append SOF `ParseError`

### Python LEN 的 `header`（必须与 C FIXED_SIZE 同一组数）

识别到 Task vs Notify SOF 之后，`header` **必须**等于该家族的固定前缀字节数，与当前生成的 `stnp_platform_config.h` 宏 / Python `ProtocolDefinition` 字段 **同一来源**（`ir/builder.py` 写入 `ProtocolIR.task_fixed_size` / `notify_fixed_size`）：

```text
STNP_TASK_FIXED_SIZE   == protocol.task_fixed_size
    == 2 + (2 if seq_enabled else 0) + 1 + 1 + 1
    # SOF(2) + SEQ(0|2) + TARGET(1) + CODE(1) + LEN(1)

STNP_NOTIFY_FIXED_SIZE == protocol.notify_fixed_size
    == 2 + (2 if seq_enabled else 0) + 1 + 1 + 2 + 1
    # SOF(2) + SEQ(0|2) + SOURCE(1) + CODE(1) + RESULT(2) + LEN(1)
```

`header` **包含** SOF 与 LEN 字节（LEN 是此前缀最后 1 字节）。**不包含** PAYLOAD，**不包含** CRC。  
**禁止**用 `STNP_TASK_HEADER_SIZE` / `STNP_NOTIFY_HEADER_SIZE`（那两宏是 2，只表示 SOF）。  
Python `_header_size(is_task)` **必须**继续返回 `self.protocol.task_fixed_size if is_task else self.protocol.notify_fixed_size`，禁止另算一套。

LEN 路径（与 C `_try_complete_frame` 在 `g_parse_len < FIXED_SIZE` 时 `return STNP_IDLE` 对齐）：

```python
header = self._header_size(is_task)
if len(self.buffer) < header:
    return out   # 等更多字节。禁止 yield/append ParseError("len")。禁止滑窗。
payload_len = self.buffer[header - 1]
if payload_len > self.protocol.max_payload:
    self.protocol_errors += 1
    out.append(ParseError("len", bytes(self.buffer[:header])))  # data 必须是这一刀
    del self.buffer[0]
    continue
```

`ParseError("len").data` **必须**是 `bytes(self.buffer[:header])`，长度 **必须**等于该家族 `FIXED_SIZE`。C 对应 `Report(STNP_UNKNOWN_LEN, g_parse_buf, STNP_TASK_FIXED_SIZE 或 STNP_NOTIFY_FIXED_SIZE)`。

LEN / CRC 失败必须 yield `ParseError`，并保持现有计数：`protocol_errors++` / `crc_errors++`。SOF **禁止**增加这两个计数。

`core/__init__.py.j2` 必须导出 `ParseError`。

### Python SOF 必须改为逐字节滑动

0.9.0 锚点 `frame.py.j2` 约 L70–77：`_find_sof` 失败时 `del self.buffer[:-1]`；命中且 `offset>0` 时 `del self.buffer[:offset]`。

0.9.1 **禁止**这两条 bulk delete。SOF 猎寻必须与 C 对齐：只看 buffer 前 2 字节；不是协议 SOF 就丢掉恰好 1 字节，然后继续。最终「当 `unknown_report_sof` 与两道闸都开时，SOF 回调次数 = 丢掉的字节数」。

`_rx_loop`（`runtime.py.j2`，0.9.0 锚点约 L190–210）：

1. `feed` 之后，`crc_errors` / `protocol_errors` 累加到 `stats` 的现有逻辑必须保留（禁止因 ParseError 再加一次）。
2. 遍历返回值：`ParseError` **禁止** `put` 进 Dispatcher，**禁止** `rx_frames++`。两闸都开时在 RX 线程调 `_report_unknown`。`reason in {"len","crc"}` 时 `debug.bp("parse_resync")` 每个 ParseError 一次。切片 C 的计数器增量路径 **必须**在 B 落地时删除；**禁止**两条路径叠加。SOF `ParseError` **禁止**打 `parse_resync`。
3. `TaskFrame` / `NotifyFrame`：`rx_frames++`，`Dispatcher.put` 如旧。

不可路由 Task / 未知 Notify 在 Dispatch 线程的 `_dispatch_task` / `_dispatch_notify` 里报，不走 `ParseError`。

## 同一回调，不同层

| reason | 层 | `data` 内容 | 何时密 |
|---|---|---|---|
| SOF | Parse | 被丢掉的那 **1** 字节 | 默认不上报。第二开关打开后次数 = 滑掉字节数 |
| LEN | Parse | C：滑 1 之前的帧头，`length = STNP_TASK_FIXED_SIZE` 或 `STNP_NOTIFY_FIXED_SIZE`。Python：`bytes(self.buffer[:header])`，`header` 定义见上节（与那两个宏同一字节数）。buffer 短于 `header`：**禁止**报 LEN | 偶发 |
| CRC | Parse | 候选帧已齐的那一段（滑 1 之前）。C：`g_parse_buf`，`length = need`。Python：`bytes(self.buffer[:total])` | 噪声时可能密 |
| TASK | C：Enqueue 失败且非 BUFFER；Py：`_dispatch_task` 未知 target/cmd | C：完整候选，`g_parse_buf`/`need`。Python：`frame.raw` 非空则用 `raw`；`raw` 为空 **禁止**报成成功路径 | 对端乱打 target 才会密 |
| NOTIFY | 仅 Python：独占链末端仍无人认领 | `frame.raw` 非空 **必须**用 `raw`。仅当 `raw` 为空（parser 填好后不应发生）才允许合成：`bytes((frame.source, frame.notify_code)) + frame.result.to_bytes(2, "little") + frame.payload` | 见下 |

合法 Task/Notify 帧不是 unknown。即使 unknown 已 enable，业务帧也禁止进本回调。

### SOF 默认不上报（第二开关，不是主开关）

```c
#ifndef STNP_UNKNOWN_REPORT_SOF
#define STNP_UNKNOWN_REPORT_SOF 0
#endif
```

放在 `stnp_unknown.h.j2`。`stnp_platform_config.h.j2` **禁止**强行定义为 1。

```python
runtime.unknown_report_sof = False  # 默认
```

1 字节滑动是同步状态机本身（冻结规范 §3.8）。默认上报会把 RING 噪声变成回调风暴。要抓线噪声必须同时：两道闸打开 **并且** 本开关为 1/True。

### NOTIFY 分类（依赖切片 A）

独占链：`模块认领 → 全局 fallback →（仍无人认领）unknown NOTIFY → drop`。

- **C**：全局恒可调用 → **C 的 unknown NOTIFY 在 0.9.1 禁止触发**。
- **Python**：`_notify_callback is None` 且模块未认领（A 的行 G）→ 两闸都开时 `reason="notify"`。覆盖 0.9.0 的静默丢。已挂 `@stnp.on_notify`：unknown 必须 0 次，全局 1 次（raw）。

## C 插入点（函数名 + 前后关系）

文件：`templates/c/Core/stnp_core.c.j2`。必须 `#include "stnp_unknown.h"`。

### `_try_complete_frame`（由 `STNP_Process` 调用，属 Process 层）

**SOF 猎寻**（`is_task==0 && is_notify==0` 的 `continue` 循环）：

1. 若 `STNP_UNKNOWN_REPORT_SOF` 为 1：`STNP_UnknownFrame_Report(STNP_UNKNOWN_SOF, g_parse_buf, 1U)`
2. `_parse_shift(1U)`
3. `continue`  
**禁止**在此打 `STNP_BP_PARSE_RESYNC`（见 04）。

**LEN**（`payload_len > STNP_PAYLOAD_MAX`，Task 与 Notify 各一处）：

1. `Report(STNP_UNKNOWN_LEN, g_parse_buf, <对应 FIXED_SIZE>)`
2. `_parse_shift(1U)`；`*complete = 1`；`return STNP_ERR_LENGTH`

**CRC / 结构**（`STNP_Frame_ParseTask` / `ParseNotify` 失败）：

1. `Report(STNP_UNKNOWN_CRC, g_parse_buf, need)` — **必须在** `_parse_shift(1U)` **之前**
2. 再滑 1、`*complete = 1`、返回原错误码

**Task 入队**（`STNP_Runtime_EnqueueTask` 之后，0.9.0 锚点约 L135–147）：

```c
result = STNP_Runtime_EnqueueTask(...);
if (result == STNP_ERR_BUFFER)
{
    return result;   /* 禁止 Report；禁止 shift */
}
if (result != STNP_OK)
{
    STNP_UnknownFrame_Report(STNP_UNKNOWN_TASK, g_parse_buf, need);
}
_parse_shift(need);
*complete = 1U;
return result;
```

不可路由（`STNP_ERR_TARGET` / `STNP_ERR_COMMAND`）必须在 shift **之前** Report。队列满不是 unknown。

Notify 入队：`STNP_ERR_BUFFER` 同样禁止 Report、禁止 shift。Notify **禁止**在入队时当 unknown。

### `STNP_Process` 的 `g_parse_len >= STNP_FRAME_MAX_SIZE` 分支

这是 return 式 LEN。必须在 `_parse_shift(1U)` 之前 `Report(STNP_UNKNOWN_LEN, g_parse_buf, g_parse_len)`，然后滑 1、返回 `STNP_ERR_LENGTH`。

## Python `_dispatch_task` 不可路由

0.9.0 对未知 target / 未知 cmd `raise ProtocolError`，被 `_dispatch_frame` 计入 `callback_errors`。

0.9.1 必须改为：

1. 两闸都开：`_report_unknown("task", frame.raw)`（`raw` 非空 **必须**用 `raw`；空则禁止报成成功路径）
2. **禁止**再 `raise ProtocolError`（因此本路径禁止增加 `callback_errors`）
3. **禁止**调用 CMD `.func`
4. 帧本来就不在 C Job 队列；Python 侧已经出队，丢弃即可

```c
static void OnUnknown(STNP_UnknownReason reason, const STNP_U8 *data, STNP_U16 length)
{
    (void)data;
    if (reason == STNP_UNKNOWN_CRC) { g_crc_noise++; }
    else if (reason == STNP_UNKNOWN_TASK) { g_bad_target++; }
}

void App_Init(void)
{
    STNP_UnknownFrame_SetCallback(OnUnknown);
    STNP_UnknownFrameCallback_Enable(STNP_ENABLE);
}
```

Python：

```python
@stnp.on_unknown_frame
def on_unknown(reason, data):
    print(reason, len(data), data[:16].hex())

stnp.unknown_frame_callback_enable()
```

### 例：CRC 错，随后真帧仍能解析

```text
# 回调一次
reason=crc data=aa5501...   # 滑 1 之前的候选前缀

# 业务仍到达
TASK ChassisMain CHASSIS.MOVE ...
```

默认未 enable：上面的用户回调 **一次都不进**。Python CRC 仍计入 `stnp.stats.crc_errors`。

### 例：不可路由 Task

对端打 `TARGET=0x09`（本地没有该 Instance）。

```text
reason=task data=aa5509...   # 完整候选帧被消费，不入 Job
```

C：`STNP_Process` 仍返回 `STNP_ERR_TARGET` / `STNP_ERR_COMMAND`，另加回调。  
Python：禁止再靠 `callback_errors` 充当本事件。

### 例：SOF 噪声（默认仍静默）

```text
# unknown_report_sof=False / STNP_UNKNOWN_REPORT_SOF=0（默认）
# 无回调，parser 照旧每次滑 1 字节

# 第二开关打开 且 两道闸都开之后
reason=sof data=b'\x00'
reason=sof data=b'\xff'
reason=sof data=b'\x13'
# 次数 = 滑掉的字节数 → 用户自己节流
```

只开两道闸、不开第二开关：SOF 回调必须 0 次。

### 例：Python 未知 Notify

无 `@stnp.on_notify`，模块未认领，unknown enable：

```text
reason=notify data=<source+code+result+payload 的原始候选>
```

已挂 `@stnp.on_notify`：unknown **0** 次，全局 1 次（raw）。

## 层边界

```text
Transport_Receive / transport.read     禁止回调（只拷贝字节）
        │
        ▼
Parse（C: _try_complete_frame；Py: StreamParser.feed）
        SOF(第二开关) / LEN / CRC
        │
        ▼
Enqueue Task：Router 失败 → UNKNOWN_TASK（C，Process 层；shift 前）
Enqueue Notify：不路由，照旧入队
        │
        ▼
Dispatch：独占 Notify（A）；Python 未知 Notify / 未知 Task
```

## 测试要点（全部是断言，不是建议）

落点 **必须**按 05「B 测试映射」放到 `tests/test_generate_multi.py`（C harness）与 `tests/test_generate_python.py`（Python），编号 1–9 与下表对齐。

1. 默认：LEN/CRC/坏 target **不**进用户回调。
2. enable 但未 set（fn 仍 NULL）：零调用。set 但未 enable：零调用。
3. enable + CRC 错：1 次 `crc`；随后仍能解析嵌套真帧。
4. enable + 未知 TARGET：1 次 `task`；帧不入 Job；C 队列满（`STNP_ERR_BUFFER`）回调 0 次且 buffer 不滑。
5. SOF 噪声默认 0 次；第二开关 + 两闸都开后次数 = 滑掉的字节数。Python 喂 `N` 字节且其中无协议 SOF、最后 1 字节保留：回调 `N-1` 次。
6. Python：无 `on_notify` + 未知 notify → 1 次 `notify`；有 `on_notify` → unknown 0、全局 1。
7. C：未知 notify_code + 模块未认领 → 只全局，unknown 0。
8. 合法协议帧（含业务 Notify）即使 unknown enable 也不进本回调。
9. 用户 unknown 回调 `raise`：运行时不崩；`callback_errors` 不增加。
