## 二、错误分级

| 级别 | 语义 | 是否影响退出码 | 呈现 |
|---|---|---|---|
| `error` | 阻断性失败，当前命令无法继续，产出不可信 | **是**（按第五节映射为 1 / 2 / 3） | `{file}:{line}:{col}: error[{code}]: {message}` |
| `warning` | 可继续，但结果可能非预期；用户应知悉 | **否**（退出码保持 0） | `{file}:{line}:{col}: warning[{code}]: {message}` |
| `note` | 纯信息，例如统计、被跳过的对象 | **否**（退出码保持 0） | `{file}:{line}:{col}: note[{code}]: {message}` |

规则：
- 每级对应一个 `level` 字符串，直接进入输出行首。
- 只有 `error` 参与退出码判定；`warning` / `note` 即使存在也不改变退出码。
- `warning` / `note` 的开关来自 `stnp.build.json` 的 `validations` 段（字段 `id` / `level`，默认全列全启用）；`validations` 把某校验项降级为 `warning` 时，该错误码以 warning 呈现且不再阻断。
- 本轮**不为任何报错点预设 `warning` 默认值**：第一节全部报错点默认 `error`；`warning` / `note` 是机制能力，供 `validations` 配置启用。

## 三、错误码方案

### 3.1 分段契约（不得自创段）

| 段 | 含义 | 归属阶段 |
|---|---|---|
| `E1xxx` | 加载格式 | 加载期 |
| `E2xxx` | 校验 | 校验期 |
| `E3xxx` | 构建 | 构建期 |
| `E4xxx` | 生成写出 | 生成期 |
| `E9xxx` | 内部 | 任意阶段的兜底 |

### 3.2 段内分配规则

- 形式固定为 `E` + 4 位十进制。首位为段号（1/2/3/4/9），后三位为段内序号。
- **加载期 E1xxx**：`E1001–E1099`。`E1001–E1050` 为「输入解析」，`E1051–E1099` 为「配置 / 环境」。
- **校验期 E2xxx**：`E2101–E2199`，按语义档位分配：`E2101–E2129` 名称与重复、`E2130–E2139` 取值范围、`E2140–E2159` 引用完整性、`E2160–E2179` 路径安全。
- **构建期 E3xxx**：`E3001–E3099`，按约束类别顺序分配。
- **生成期 E4xxx**：`E4001–E4099`，按「分派 → SDK → 路径安全 → 写出 → 模板」顺序分配。
- **内部 E9xxx**：`E9001` 未捕获异常、`E9002` 内部不变量破坏。**仅这两个取值**。
- 已分配错误码**只增不改**；删除报错点时其码位保留（置为 reserved），不复用。

## 四、编译器风格输出格式

### 4.1 单条诊断格式

```
{file}:{line}:{col}: {level}[{code}]: {message}
{line:>5} | {source_line}
      | {pad}^ {annotation}
help: {help_text}
```

- `{file}`：相对当前工作目录的路径（如 `examples/min_demo.stnp`）；无对应文件时用 `<internal>`。
- `{line}`：1 基行号；`{col}`：1 基列号。
- `{level}`：`error` / `warning` / `note`。
- `{code}`：第三节错误码，形如 `E2102`。
- `{message}`：中文一句话，以事实结尾，不带句末句号。
- 上下文行：默认打印**出错行 1 行**（`{line:>5} | ` 前缀），并在下一行用空格 + `^`（或 `^^^` 覆盖 token）指向列。
- `help:` 行：可选。仅当存在可执行的修复建议时打印，单行，缩进不参与对齐；无建议则整行省略。
- 多条诊断之间空一行分隔。

### 4.2 多错误排序

1. 按 `file` 字典序（`<internal>` 永远排最后）。
2. 同文件按 `line` 升序。
3. 同行按 `col` 升序。
4. 同位置按 `code` 升序。
5. 全部相同则按发现顺序稳定排序。

### 4.3 何时省略 `line:col`

- 错误**不对应具体源位置**（内部错误、输出写出失败、config 级错误）时，省略 `:{line}:{col}`，只输出 `{file}: {level}[{code}]: {message}`。
- 错误**连文件都没有**时，用 `<internal>: {level}[{code}]: {message}`。
- 位置不完整时（例如只有行没有列），退化为 `{file}:{line}: {level}[{code}]: {message}`。

### 4.4 示例（覆盖五个阶段）

加载期·JSON 语法：
```

      |             ^
help: 检查该位置前后的逗号与括号配对
```

加载期·schema：

校验期：

   30 |     {"name": "MOTION", "return_codes": []}

## 五、错误码 → 退出码映射

严格限定四个取值：`0` 成功 / `1` 校验或生成失败 / `2` 用法参数错误 / `3` 内部错误。

| 来源 | 错误码段 | 级别 | 退出码 | 说明 |
|---|---|---|---|---|
| 加载失败 | `E1xxx` | error | **1** | 工程 / 构建文件格式、schema、配置失败 |
| 校验失败 | `E2xxx` | error | **1** | IR 校验失败 |
| 构建失败 | `E3xxx` | error | **1** | IR 构建约束失败 |
| 生成失败 | `E4xxx` | error | **1** | 分派 / SDK / 路径 / 写出失败 |
| 内部缺陷 | `E9xxx` | error | **3** | 生成器自身问题 |
| 用法错误 | 无错误码（argparse 自带） | error | **2** | 未知子命令、缺必填参数、非法选项值 |
| 任何 warning / note | 任意 | warning/note | **不改变** | 默认 0；不影响成功判定 |
| 成功 | — | — | **0** | 无 error 级诊断 |

补充规则：

1. **退出码 2 只来自 CLI 用法层**：由 `argparse` 解析失败触发（`argparse` 自身 `sys.exit(2)`），不携带 `E` 码。业务侧的「非法 target」不再走 2（见第六节 D18/D19 归并）。
2. **退出码 1**：出现任意 `E1/E2/E3/E4` 的 `error` 级诊断即返回 1；`check` 子命令的「golden 不一致」也返回 1（现状已如此，`cli.py:73`）。
3. **退出码 3 的兜底**：`cli.main` 最外层捕获所有非 `StnpError` 的 `Exception`，按 `E9001` 呈现并返回 3；`E9002` 由内部断言主动抛出，同样返回 3。
4. 退出码判定发生在**所有诊断收集完毕之后**：只要存在 error 级诊断，无论后续阶段是否继续执行，最终退出码按上表取「最严重阶段」对应值；多段同时出错时，优先级 `3 > 1`（内部错误优先）。
5. `KeyboardInterrupt` 不映射为 3，交还 shell 处理（保持默认 `SystemExit` 行为）。

### 6.3 现有 `NotImplementedError` 分支（cli.py 两处 `return 2`）的归并

- 两处分支（`cli.py:43` 与 `cli.py:55`）都是 `ensure_supported_generation_targets` 的守卫，服务于已被 D17/D18/D19 否决的「多目标 / 目标不支持 → 退出码 2」语义。
- **归并方式**：
  1. **删除** `generation.ensure_supported_generation_targets` 与其在 `cli.py` 的 import / 调用 / `except NotImplementedError` / `return 2`（两处）。
  2. 非法 `target` 由 `stnp.build.schema.json` 的 `enum ["c","python"]` 在**加载期**拒绝 → `LoadError` **E1015**，退出码 **1**。
  3. `generation.ensure_supported_generation_target`（单数）保留为生成期兜底 → **E4001**，退出码 **1**；正常路径不应触发（schema 已挡）。
  4. 删除两处后，`generate` 与 `check` 共用 `_run` 外层的单一 `except StnpError` / `except Exception` 结构，退出码 2 只保留给 `argparse`。
- 影响：`cli.py` 的 `try/except NotImplementedError` 全部消失；`E4002` 作为「遗留复数入口」码位保留但不再由 CLI 触发（仅测试或旧调用方可能命中）。

### 6.4 未捕获异常归入退出码 3 的落点

- 在 `cli.py` 顶层 `main()` 中，`_run(argv)` 之外包一层 `try/except Exception as exc`：
  - 若 `exc` 是 `StnpError` → 用其 `code/level/file/line/col/message/help` 走 `diagnostics.render_all()`，返回其映射退出码。
  - 否则 → 构造 `InternalError(E9001)`，`file="<internal>"`，省略 `line:col`，返回 **3**。
- `E9002` 用于生成器内部不变量断言（如 IR 字段自洽性），由内部代码主动抛 `InternalError`，同样返回 3。
- 调试模式（如 `STNP_EDITOR_DEBUG=1`）下，`E9001` 额外打印完整 traceback，但退出码仍为 3。
