# STNP 0.9 规格变更清单（逐节改前／改后）

## 0. 本清单的定位与使用方式

- **目标文档**：`docs/STNP_SPEC_0.9.md`（权威目标规范）。
- **性质**：本清单只列「改前 → 改后」，**不修改**目标规范本身；落地阶段据此逐条执行。
- **唯一依据**：`docs/IR-CLI-决策.md`（用户裁定）与配置拆分补充裁定。
- **表列契约**：每张表固定五列 —— `位置 | 变更类型（删/增/改）| 改前 | 改后 | 依据裁定`。
- **覆盖规则**：目标规范的每个顶层章节（§1…§10 + 两个附录）都必须在下方出现；无变更的章节与子节同样逐行列出并写明「无变更」。
- **定位约定**：本清单以章节号与字段名定位，不使用行号引用；不书写任何代码符号（类名、函数名、常量名、模块内标识符），只使用 JSON 字段名、章节号与行为／数据的自然语言描述；不贴代码块。
- **三处强制修订**（本清单相对原清单的强制口径，优先于原清单的同类表述）：
  1. **示例处置改为人工重写**：示例工程不在本清单的逐字段迁移范围；0.9 落地时由人工重写，不逐字段迁移。本次仅删除其中已废弃的字段。
  2. **旧格式一律不承接**：不设复数目标形态、候选目标兜底或旧版本形态兜底；不设任何过渡层或双读路径、不设 shim、不设弃用告警；`additionalProperties: false` 直接拒绝旧格式；读到旧格式即失败，不做适配。
  3. **`config.json` 保留为生成器内部资源**：不删除；其内部资源（schema 定位、模板定位、内部目录名、SDK 注册表）留在生成器内部，不进用户可编辑的构建配置文件；仅输出目录命名与示例产出开关迁出到构建配置文件。
- **关联方案**（阶段一其余交付物；本清单与它们的结论保持一致）：报错处理机制、配置拆分与 Schema、IR 生成侧 CLI、GUI 清理与迁移。
